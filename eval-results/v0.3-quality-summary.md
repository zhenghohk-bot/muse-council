# v0.3.2 对话质量小结

## 本轮目标

v0.3.2 让先行者的发言长度服从内容，而不是服从统一模板：能简短说清时只显示一个气泡；确实需要补充理由、区分或追问时，允许一次完整发言在自然停顿处拆成两个顺序气泡。

完整发言仍只保存为一条 `RoundtableMessage`，并保留同一个 message id，历史记录、行动卡溯源、金句提炼与评测不会把两个展示气泡误判成两轮发言。

## 验收结果

| 场景 | 分数 | 结果 | 主要验证 |
| --- | ---: | --- | --- |
| 朋友关系与边界 | 88 | 通过 | 三位先行者长短发言混合；长发言按语义拆分；交锋不再重复第一轮；行动卡与金句卡可追溯 |

本次真实评测无 API 降级、无确定性硬失败。人物区分 88、重复控制 85、行动卡 90、金句卡 95。`npm run build` 与 `npm run check:harness` 通过。

## 本轮 Harness 改进

- Pioneer turn 上限由机械的短句限制调整为 124 字，但 Prompt 明确要求：68 字内能讲清就及时停止，不强制每位先行者展开长段。
- `segments` 只负责展示，限制为 1–2 段、每段最多 68 字，并校验拼接后必须与完整发言一致。
- 第二段必须增加理由、代价、区分或追问；相似度过高会被 OutputGuard 判为重复。
- 分段优先选择句号、问号、感叹号和分号，其次才是冒号与逗号，减少阅读中的截断感。
- 播放器逐段揭示同一位先行者的内容，头像只出现一次；用户点击圆桌仍可跳过当前阅读停留。
- 追问回复沿用同一套分段与播放机制，旧的本地历史没有 `segments` 时自动回退为单气泡。

## 实机检查

- 真实圆桌中同时出现一段式与两段式发言，没有强制统一长度。
- 两段式发言顺序浮现，第二段使用续接样式；头像、文本与底部输入框没有互相遮挡。
- 播放结束后才解锁“收束并生成行动卡”，阶段状态保持正确。

## 已知边界

- 本轮针对关系边界场景做真实模型验收，没有重新跑完整评测集。
- 云端数据库暂只保存完整 `content`，`segments` 当前由本地会话保留；恢复旧会话不会丢内容，但云端恢复展示分段需在历史功能上线时补迁移。
- 模型仍可能偶尔使用略抽象的比喻，后续继续通过真实失败样本扩充语言清晰度规则。
