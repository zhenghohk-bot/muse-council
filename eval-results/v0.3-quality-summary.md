# v0.3.1 对话质量小结

## 本轮目标

v0.3.1 在 Conversation Director 之上增加三档支持模式，解决“克制心理归因”与“保留情绪支持”之间的冲突：

- `unknown_cause`：承认感受真实，观察变化，但不替用户补写原因。
- `named_emotion`：直接承接用户亲自说出的羞耻、失落等情绪，并帮助分辨触发、需要与选择。
- `experience_context`：分析用户已提供的事件、感受与选择；更深推测仍须写成问题或可能性。

同时修正了第一人称误判、咨询术语、人物兜底同质化、跨场景交锋和行动卡主线脱节等问题。

## 验收结果

| 场景 | 修改前 | 最终分数 | 结果 | 主要验证 |
| --- | ---: | ---: | --- | --- |
| 原因不明的晨间沉重 | 79 | 88 | 通过 | 不发明原因；保留温柔承接；人物区分从 72 提升到 88，重复控制从 60 提升到 82 |
| 用户明确说出羞耻 | 84 | 87 | 通过 | 可以直接承接“羞耻”；不美化成成长信号；交锋与行动卡贴合本题 |
| 朋友关系与边界 | 87 | 85 | 通过 | “不知道该继续还是退出”不会误判成原因未知；术语改为日常中文 |

三次最终验收均无 API 降级、无确定性硬失败。`npm run build` 与 `npm run check:harness` 通过。

## 本轮 Harness 改进

- 支持模式由确定性分类器写入 session，并随用户追问升级；例如用户后续说“我意识到那是羞耻”，圆桌会从原因未知切换到已命名情绪。
- Prompt 明确区分“情绪确认”与“原因推断”：可以说“这确实不好受”，不能说“你其实在哀悼”。
- 原因未知模式保留安全兜底，但每位先行者使用不同观察路径，不再统一输出记录表。
- OutputGuard 不再把“自我”中的“我”误认成第一人称，并拦截未说完整的条件句、术语和过度文学化表达。
- 评测集新增已命名情绪样本，并把三档模式是否判对纳入硬性检查；独立裁判也按不同支持模式评分。

## 已知边界

- 本轮完成三个高风险场景的针对性验收，没有重新跑完整七题批次。
- 模型输出仍存在少量抽象词和轻微重复，但三类场景均已达到 MVP 发布门槛。
- 三档分类器目前使用可审计的规则和情绪词表；后续可结合真实失败样本扩充，而不急于引入不可解释的分类模型。
